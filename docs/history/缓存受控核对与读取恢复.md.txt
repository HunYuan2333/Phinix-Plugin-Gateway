# 缓存受控核对与读取恢复

日期：2026-10-04。分支：`dev`。[English](CacheRecovery.md)。本批为隔离 repository PoC 增加账号内部运维工具；没有修改客户端/框架 API、Trade 状态、物品所有权、正式索引或批准记录。

## 已交付

`RepositoryOperations` 是命名 WorkerEntrypoint，调用既有单例 SQLite DO。[命令及使用说明](../../../../Extensions/PluginStore/RepositoryWorker/ops/README.zh-CN.md) 使用标准 Wrangler 登录、本机 loopback 桥接和 strict 有界 JSON；公网 gateway 没有管理路由。PoC 显式开启 `CACHE_OPERATIONS_ENABLED`，默认继续关闭。检查导出一个 SQL 快照、条目 fingerprint 和最近 64 条持久日志，不访问 R2；Python 创建新的 0600 文件，不覆盖旧证据。

显式确认仅接受过期、没有活跃写入、身份/lease/fingerprint 与检查快照相同的 writing/uncertain 对象。SQL 先预扣一次 Class B GET；存储元数据/长度/checksum 和逐字节增量 SHA-256 都通过后，按原条目比较并提交 `verified`。它可读但仍计预留、不可淘汰、不可再次填充；已暂停账本保持暂停。查询/body/hash 超时、体积边界、并发、快照变化、对象缺失/损坏、预算耗尽及 SQL 故障均保留原容量预留和历史计数。没有释放容量、任意 SQL、删除/purge、清零、周期滚动或初始化修复功能。

`cache.recovery_bytes_verified` 只说明字节通过，`cache.recovery_confirmed` 在 SQL 提交之后输出；持久 journal 与外部 request/lease/period 日志关联失败。自定义日志不输出任意异常、URL 或凭据。原生测试发现 RPC 序列化缺口：strict JSON 返回 null-prototype map，桥接须先转换为普通可序列化对象。
